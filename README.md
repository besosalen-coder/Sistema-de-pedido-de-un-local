# Sistema de pedido de un local
Sistema de Pedidos de un Local de Comidas  Sistema en Java que modela el flujo de pedidos de un local de comidas: productos del menú, planes de fidelidad de clientes y medios de pago, calculando el total de cada pedido y la facturación del día.  Desarrollado con TDD (Test-Driven Development): cada clase surgió a partir de un test, sin anticipar diseño.  Qué resuelve Un pedido puede incluir distintos tipos de producto (platos, bebidas, combos) sin que el código pregunte de qué tipo es cada uno. El total se calcula en 3 pasos: suma de productos → descuento según el plan del cliente → ajuste del medio de pago. Un cliente puede cambiar de plan de fidelidad en cualquier momento, y eso afecta sus próximos pedidos. El local puede calcular su facturación total sumando todos los pedidos del día. Diseño Decisión	Por qué Producto como interfaz	Plato, Bebida y Combo no tienen relación "es un" entre sí, solo comparten el comportamiento de calcular precio PlatoDelDia extends Plato	Sí hay relación "es un" y estado compartido (precio base) Combo Familiar sin subclase propia	La única diferencia con Combo es el % de descuento → se resuelve con un parámetro, no con herencia ModoPago y PlanFidelidad como interfaces	Sin estado compartido, y se usan también fuera del contexto de un pedido  Sin un solo instanceof en el código de producción — el polimorfismo resuelve todo.
